# 두 번째 모델 계열: Qwen2.5-1.5B-Instruct — `npu-lora check` 와 LoRA 품질 (RNGD vs A100)

- **Date**: 2026-10-20 ~ 2026-10-21
- **Task**: #24
- **Host / device**: npu-node-2 RNGD 1장(npu0, `furiosaai/furiosa-llm:latest` digest `sha256:37a85288…`, furiosa-torch 2026.2.0,
  드라이버·펌웨어 2026.4.0) / 같은 노드 A100 80GB PCIe(`vllm/vllm-openai:v0.11.0`, torch 2.8.0+cu128). 평가 같은 A100, vLLM 0.11.0.
- **Commit**: RNGD `b3a5e90`, A100 `16e17aa`(perf/21 브랜치, #26 — LoRA 경로는 `main` 과 같다). Qwen2 블록은 `main`(#16 에 들어온 #9 코드).

## Question

Llama 가 아닌 dense 모델(q/k/v bias 가 있는 Qwen2)이 RNGD 에서 `npu-lora check`(장치 대 CPU 기울기)를 통과하는가?
같은 LoRA 레시피로 RNGD 학습이 A100 학습과 같은 품질을 내는가?

## Setup

- 모델 `Qwen/Qwen2.5-1.5B-Instruct`(28층, H 1536, I 8960, 12/2 head, head_dim 128, 어휘 151,936, q/k/v bias).
- 첫 컴파일(장치 없이, S=128 LoRA r16 q·v): 6,339 s — 레이어 순전파 15조각, 역전파 39조각(`experiments/data/w7/compile-qwen15.parts.txt`).
- `npu-lora check --layers 2 --seq-len 128`(무작위 입력, B 를 N(0, 0.01) 로 채움).
- 학습(두 장치 동일): LoRA r=16 α=32 q·v, S=128, lr 2e-4(warmup 10, cosine), 400 step × accum 4, grad clip 1.0, seed 0, NSMC train 4,000개.
- 평가 `npu_lora.bench`: NSMC 시험 1,000, MMLU 400, temperature 0.

## Command

```bash
M=Qwen/Qwen2.5-1.5B-Instruct
python3 -m npu_lora.cli compile --model $M --seq-len 128 --cache-dir /cache/furiosa
python3 -m npu_lora.cli check --model $M --backend furiosa:auto --cache-dir /cache/furiosa --seq-len 128 --layers 2
python3 -m npu_lora.cli train --model $M --data /mnt/store/datasets/quality/nsmc_train.jsonl --backend furiosa:auto \
  --cache-dir /cache/furiosa --seq-len 128 --steps 400 --accum 4 --lr 2e-4 --rank 16 --alpha 32 --targets q,v --seed 0 \
  --run-name w7-qwen15-rngd --out /mnt/store/w7/out/qwen15-rngd                   # A100: --backend cuda:0
python3 -m npu_lora.bench --model $M --adapter lora400-rngd=/mnt/store/w7/out/qwen15-rngd \
  --adapter lora400-cuda=/mnt/store/w7/out/qwen15-cuda --gpu-mem 0.5 \
  --task nsmc=/mnt/store/datasets/quality/nsmc_test.jsonl --task mmlu=/mnt/store/datasets/quality/mmlu.jsonl --out qwen15.json
```

## Results

### `npu-lora check` — **실패**

| | 값 | 기준 |
|---|---:|---:|
| loss (RNGD / CPU) | 18.1975 / 18.2048 (상대차 4.0e-4) | < 1e-2 통과 |
| 기울기 최대 상대오차 | **0.444** (0층 q 의 B, cos 0.902) | < 5e-2 **실패** |
| q 의 A·B (0층 / 1층) | 0.427·0.444 / 0.259·0.265 (cos 0.90–0.97) | |
| v 의 A·B (0층 / 1층) | 0.138·0.156 / 0.125·0.128 (cos 0.988–0.992) | |

Llama-3.1-8B 는 같은 검사에서 최대 2.5 %(cos ≥ 0.9997)였다. Qwen2 블록에서 RNGD 기울기가 **조용히 틀린다**(컴파일 오류 없음).
q 쪽이 가장 크게 틀리고 q 에는 bias 와 RoPE 가 붙으므로 bias 가 있는 q 경로의 조각이 의심되지만 `diagnose.compare_parts` 로 조각을 좁히지는 않았다.
학습 중에도 증상이 보인다: RNGD 실행의 step loss 가 400 step 중 11번 음수였다(최소 −0.012; cross-entropy 는 음수일 수 없다). A100 은 0번.

Raw: `experiments/data/w7/qwen15-check-rngd.json`, `qwen15-lora-{rngd,a100}.jsonl`, `bench-qwen15.json`.

## Conclusion

Qwen2 계열은 RNGD 에서 컴파일되고 학습되며, 이 과제의 품질은 A100 학습과 같다(NSMC 0.2%p, MMLU 0.5%p 차). 그러나 `npu-lora check` 는
실패한다 — q LoRA 기울기 상대오차 44 %, head loss 가 ~0.01 nat 틀려 음수 loss 가 나온다. 품질이 같은 것은 Adam 의 정규화와 짧은 학습이 기울기
방향 오차(cos 0.90)를 견딘 결과로 보이며, 정확한 기울기를 주장(논문 C2)하려면 Qwen2 를 "지원"이라 쓰기 전에 고쳐야 한다.
다음: `diagnose.compare_parts` 로 틀린 조각 찾기(q bias + RoPE 조각, 151,936 어휘 head 조각), 수정 후 check 재실행. Qwen3 는 하지 않았다.
